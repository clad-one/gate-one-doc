Usage events and plugins

Durable, subscribed, pseudonymized events delivered to signed out-of-process plugins.

Useful if you want to…

  • meter or audit usage without putting code on the request path;

  • keep operational metrics (auth failures, errors, request counts) in your own system;

  • integrate a commercial or closed-source extension without granting it access to tokens or identities;

  • survive a plugin outage without losing the events you declared durable.

Events are produced only for subscribed types. If no plugin subscribes to request, Gate One produces no request event at all. Free/self-hosted Gate One is operational-only: it ships no commercial metering.

Event types

TypeProduced whenDefault durability

request

after a response, if subscribed

best effort

auth

login, logout, callback, back-channel logout, revocation

zero loss

error

401/403/502/5xx, provider unavailable

window

billing

a billable unit (reserved for a later plugin)

zero loss

audit

admin, reload, plugin load/revoke, 403

reserved

request and error cannot use fsync: "always": the proxy emitter cannot fsync before a streaming response. Use window_ms for them.

Event shape

{
  "schemaVersion": 1,
  "type": "auth",
  "ts": "2026-11-02T12:00:00Z",
  "instanceId": "gw-1",
  "epoch": "2026-11-02T11:00:00Z",
  "tenant": "mycompany",
  "subjectId": "v1....",
  "action": "login",
  "sessionId": "...",
  "status": 200,
  "authResult": "ok"
}

Rules:

  • no token, cookie, raw query string, email or username;

  • route is the normalized pattern, never the raw URL;

  • the user is an opaque subjectId: v1. + base64url(HMAC-SHA256(secret, issuer "\x00" sub));

  • the secret is per deployment, shared by every instance, and held only by the producer. A plugin never receives it.

The application may receive the same identifier as a backend header:

X-Gate-One-Subject: v1.<base64url>

It is added after authentication, never accepted from a client, and is not an authentication token.

WAL and backpressure

  • one WAL per (node, event type);

  • one cursor per (type, subscriber);

  • a node budget (50 MiB by default) split into per-type shares; the sum of shares must not exceed the budget;

  • admission reserves space before authentication and before the backend call;

  • a full durable share answers the affected route with a targeted 503, Retry-After and a usage_unavailable body;

  • healthz, readyz, the auth probe and the usage endpoints are exempt;

  • fsync: "always" (zero loss) appends and fsyncs before the response; a failed fsync is a 503;

  • fsync: "window_ms" groups commits; a crash may lose the current window;

  • a subscriber beyond maxLagBytes either blocks (503 until it catches up) or drops (cursor advances to the lag limit, events become evictable, the plugin is marked degraded);

  • a new subscriber starts at the tail; there is no historical replay.

On a login, auth is fail-closed: if the event cannot be written, Gate One returns 503 before creating the session. Logout and back-channel logout are best effort: the revocation must succeed even if auditing fails.

Signed plugins

A plugin is an out-of-process HTTP/JSON service. It is never loaded into the Gate One process and never decides authentication.

{
  "usage": {
    "dir": "./usage-wal",
    "nodeId": "gw-1",
    "subjectSecretEnv": "GATE_ONE_SUBJECT_SECRET",
    "pluginSecretEnv": "GATE_ONE_PLUGIN_SECRET",
    "trustStore": "trust-store.json",
    "types": {
      "auth":  { "shareBytes": 10485760, "fsync": "always" },
      "error": { "shareBytes": 10485760, "fsync": "window_ms", "windowMs": 250 }
    },
    "plugins": [{
      "name": "com.cladone.audit",
      "url": "http://127.0.0.1:9100",
      "manifest": "audit.manifest.json",
      "artifact": "audit-echo.placeholder"
    }]
  }
}

The manifest is signed (Ed25519) and declares the artefact digest, dependencies, host API and event subscription. At startup Gate One verifies:

  • the signature and the signing key against usage.trustStore;

  • the artefact digest and optional size;

  • the declared dependencies against the trust store;

  • revocation by digest;

  • host API compatibility;

  • kind (extension or auth; auth requires allowAuth).

A manifest is authoritative for the subscription (events.types, filters, maxLagBytes, onMaxLag) and the licence feature. The complete example is routes.json, audit.manifest.json, trust-store.json.

Host → plugin contract

Every call carries a short-lived signed assertion:

X-Gate-One-Assertion: base64url(payload).base64url(HMAC-SHA256)

The payload binds the audience (plugin name), an expiry and the body size. The plugin exposes:

EndpointPurpose

GET /health

readiness; a degraded plugin stops receiving new batches

POST /events

batch [{offset, event}]; the plugin commits its state, then acknowledges the offsets

Acknowledgement is transactional: the core truncates up to the minimum cursor of all subscribers. A plugin that does not acknowledge will hit backpressure, not silently lose the events it declared durable.

Reference plugin

cmd/plugin-audit-echo in the source repository is the reference consumer. It verifies the assertion, decodes the batch and logs the events; it has no dependency on Gate One internals.

export GATE_ONE_PLUGIN_SECRET=...
go run ./cmd/plugin-audit-echo -addr :9100 -name com.cladone.audit

Licensing

The core is source-available under BSL-CUSTOM. Non-auth, non-broker extensions may be closed-source or commercial under the plugin exception. Authentication adapters, broker IdP adapters and derived copies remain under the Gate One licence. A commercial plugin may declare licenseFeature; the host refuses to load it without that feature.

Limits

  • There is no public compile-time plugin API. Go plugin (.so) is not supported.

  • A plugin cannot add a pre-auth hook, register its own route, mutate the identity or change auth, securityHeaders, license, rateLimit or quota.

  • Plugins are internal-network services: no Traefik exposure, signed assertion, separate UID, no secrets in the environment, egress allow-list.

  • Long-term retention is the plugin’s policy, not the core’s.
