Plugin manifest

Generated from schemas/plugin-manifest.schema.json by scripts/gen-config-docs. Do not edit this page: edit the schema or the generator.

The signed manifest shipped with an out-of-process plugin. The operator references it from usage.plugins[].manifest; the trust store decides whether the signer and the artefact are trusted.

Fields

FieldTypeRequiredDescription

schemaVersion

integer (fixed: 1)

yes

Manifest schema version. Always 1.

kind

string (one of: extension, auth)

yes

Plugin kind. auth requires the trust store to allow auth modules; extensions cover routes, injection, events and transforms.

name

string

yes

Reverse-DNS plugin name. Must match a trust store allowedNames entry (exact or glob). Minimum length: 1.

version

string

yes

Plugin version (semantic version recommended). Minimum length: 1.

apiVersion

string

yes

Plugin API version implemented by the artefact (currently v1). Minimum length: 1.

hostAPI

string

yes

Host API constraint, for example >=1.0 <2.0 or *. Compared with the trust store coreVersion. Minimum length: 1.

publisher

string

no

Optional publisher identity.

keyId

string

yes

Signing key id; must exist in the trust store keys map. Minimum length: 1.

artifact

object

yes

The signed artefact (binary, container or OCI reference). Its digest is verified before the plugin is trusted.

dependencies

array of object

no

Other artefacts this plugin depends on. Each digest must be allow-listed in the trust store.

capabilities

array of string (one of: events, handler, inject, assets, guard, auth)

no

Declared capabilities. An extension cannot declare auth; events requires the events capability.

licenseFeature

string

no

Optional commercial licence feature required to load this plugin. The host refuses the plugin when the feature is absent.

events

object

no

Usage-event subscription. Only these types are produced for this plugin.

signature

object

yes
