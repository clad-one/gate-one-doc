= Delegated credentials

This example lets Gate One call GitHub **as the signed-in user**. The
user connects GitHub once on the connections page; the token broker
stores the token; the API route and the MCP service use it on every
request.

== File

link:/examples/delegated-credentials/routes.json[`examples/delegated-credentials/routes.json`]

[source,json]
----
{
  "tokenBroker": {
    "url": "http://token-broker:4000",
    "secretEnv": "TOKEN_BROKER_SHARED_SECRET",
    "links": {
      "services": {
        "label": "Services",
        "url": "https://login.example.com/connections"
      }
    }
  },
  "routes": [
    {
      "host": "api.example.com",
      "path": "/github/*",
      "stripPrefix": "/github",
      "backend": "https://api.github.com",
      "auth": {},
      "upstream": {
        "host": true,
        "delegated": { "provider": "github" }
      }
    },
    {
      "host": "mcp.example.com",
      "path": "/internal-github",
      "backend": "https://api.github.com",
      "auth": {},
      "upstream": { "delegated": { "provider": "github" } },
      "openapi": { "url": "http://landing/github-openapi.json", "public": false },
      "mcp": {
        "enabled": true,
        "name": "github",
        "operations": [
          { "name": "list_repos", "operationId": "list_repos" },
          { "name": "get_repo", "operationId": "get_repo" },
          { "name": "list_issues", "operationId": "list_issues" }
        ]
      }
    }
  ]
}
----

The `tokenBroker` block is declared once; the two routes differ only in
how the token is consumed.

== How it works

. The user signs in through the OIDC provider.
. On `https://login.example.com/connections` they connect GitHub.
. `api.example.com/github/*` proxies to `https://api.github.com` with the
  caller's GitHub token.
. The MCP service exposes `list_repos`, `get_repo` and `list_issues`;
  each tool call uses the same per-user token.

== Try it

[source,bash]
----
# Before connecting: the gateway answers with a connect_url.
curl -i https://api.example.com/github/user

# Connect GitHub at the URL the previous call returned, then retry.
curl -i https://api.example.com/github/user

# The same token drives the MCP tools.
curl -s https://mcp.example.com/.well-known/oauth-protected-resource | jq
curl -s https://mcp.example.com/internal-github \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"list_repos","arguments":{}}}'
----

[[notes]]
[NOTE]
====
* The token broker is internal-only; only its browser routes are exposed
  through the login host.
* `upstream.delegated` requires `auth`.
* The provider's client secret lives in the broker, never in Gate One.
* GitLab and other providers are configured in the broker, not in the
  Gate One file.
====
