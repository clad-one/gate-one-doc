= Call services with the user's credentials

== Useful if you want to…

* let a route or an MCP tool call an external API **as the user**, not as
  a shared service account;
* keep the provider's client secret out of Gate One;
* let every user reach the upstream with their own rights;
* give users a page where they connect and revoke those services.

== The two credential shapes

When a route calls an external API, the credential can be:

* **static** — one shared value for every caller, set with
  `upstream.headers` (for example a service token);
* **delegated** — the signed-in user's own token, obtained after they
  authorize the service once.

Gate One implements the delegated shape with the **token broker**.
`upstream.tokenBroker` on a route tells Gate One to fetch the caller's
token from the broker and inject it into the upstream request. It applies
to plain proxied API routes and to the REST/MCP tools a route exposes —
see link:/docs/features/mcp-tools/[MCP tools].

[IMPORTANT]
If the upstream needs the **same** credential for every caller, do not
delegate. Set it once with `upstream.headers`, for example:

[source,json]
----
"upstream": {
  "headers": { "Authorization": "Basic ${SERVICE_BASIC_AUTH}" }
}
----

Delegation is only for credentials that belong to the **individual
user**. A shared service account, a static bearer token or a Cloudflare
Access service token is simpler and has no connection page to manage.

== What delegation is not

Delegation is **not** an identity provider and **not** SSO:

* the IAM/IdP still decides *who* the user is (`auth`, `auth.identity`);
* the token broker only stores a token the user granted for one upstream
  service.

The names are easy to confuse, so see
link:/docs/iam-and-providers/[IAM, IdPs and provider types] for the
`cladone-auth` **Broker** (an OIDC issuer/IAM), the `http-bridge`
provider type and the **token broker** side by side.

== The token broker and the connections page

The token broker is a small, internal-only service: a registry of OAuth
providers plus an encrypted per-user token store. It is never exposed
directly; only its browser routes are published through the login host.

Users authorize a service on the **connections page** ("Service
connections"). Gate One links to it from the user badge as **Services**,
and shows that link only when an exposed route declares delegation.

=== For the user

1. Open **Services** from the user badge (or follow the `connect_url` a
   delegated call returned).
2. Next to the service (for example GitHub), choose **Connect** and
   authorize it at the provider.
3. The broker stores the token; the next call to a delegated route uses
   it.
4. **Disconnect** deletes the local token and, when the provider supports
   it, revokes it there too.

If the token can no longer be refreshed, the connection is marked
**reauthorization required** and Gate One sends the user back to this
page (`409 reauthorization_required` for an API call, a redirect for a
browser route).

=== Add a delegation service

A provider is a **registry entry, not code**: the token broker's
`providers.json` lists each OAuth 2.0 service (endpoints, client id,
scopes, …). Adding GitHub, Google, Slack or an internal OAuth service is
a registry entry; its client secret comes from the broker's environment,
never from the file.

Gate One only references the provider **name**
(`upstream.tokenBroker.provider`). See
link:/docs/components/token-broker/#add-a-delegation-service[the token broker] for
the fields and an example.

== Declare delegation on a route

[source,json]
----
{
  "tokenBroker": {
    "url": "http://token-broker:4000",
    "secretEnv": "TOKEN_BROKER_SHARED_SECRET",
    "links": {
      "services": {
        "label": "Services",
        "url": "https://login.example.com/connections"
      }
    }
  },
  "routes": [
    {
      "host": "api.example.com",
      "path": "/github/*",
      "stripPrefix": "/github",
      "backend": "https://api.github.com",
      "auth": {},
      "upstream": {
        "host": true,
        "tokenBroker": { "provider": "github" }
      }
    }
  ]
}
----

* `auth` is required: the broker needs an authenticated user id.
* `provider` is a broker provider name (`github`), validated against the
  broker at startup.
* the token is sent as `Authorization: Bearer …` by default; set `header`
  and `prefix` to change the header or the prefix.
* the shared secret is read from the environment named by `secretEnv` and
  is never written in the file.

[NOTE]
The `tokenBroker` block and the route are shown together because a route
that declares `upstream.tokenBroker` **requires** the top-level
`tokenBroker` block; without it the configuration is refused at load.
This is a partial extract (the providers and other routes are omitted) —
the complete file is
link:/examples/mcp-tools/routes.json[`examples/mcp-tools/routes.json`].

== When the user has not connected the service

Gate One never sends a request without credentials:

* an API/JSON call gets **401/409** with a `connect_url` the client can
  open;
* a browser (frontend) route redirects to the connections page.

[[security]]
[IMPORTANT]
====
* Gate One never stores the provider's client secret; the broker does,
  and only the broker talks to the provider's token endpoint.
* The broker is internal-only and protected by a shared secret read from
  the environment.
* Reserved header names (`Host`, `Cookie`, `X-User-*`, `X-Forwarded-*`,
  `X-Gate-One-*`) are refused for `header`.
* A delegated route requires `auth`: there is no anonymous delegation.
====
