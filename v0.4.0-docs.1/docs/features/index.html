Features

Each feature is written as useful if you want to…, with a short configuration, a complete example and anchors into the generated reference.

SSO across your apps

Useful if you want to: you want one login for several applications without changing the applications.

One authentication provider, one login host and a shared cookie domain across applications.

Feature Example

SSO across different domains

Useful if you want to: your applications live on unrelated domains and you want one IdP login without a second form.

ssoGroups declares the shared OIDC/client/session settings once, one provider per domain, and routes.hosts expands one route body across those domains.

Feature Example

Multiple identity providers

Useful if you want to: your users come from several identity providers and you already run an IAM.

Use Keycloak, Zitadel or another OIDC IAM to federate Google and other IdPs behind one issuer.

Feature Example

Embedded IAM

Useful if you want to: you want IdP federation and managed user grants without running an external IAM.

The lightweight cladone-auth broker maps IdP claims to a common roles/scopes/claims model and manages local and federated users.

Feature Example

Horizontal scaling

Useful if you want to: you need several Gate One replicas behind a load balancer.

Shared Redis session/revocation state and a common signing key make logout and revocation effective across replicas.

Feature Example

Protect APIs and MCP tools

Useful if you want to: you expose APIs or MCP tools to authenticated users and machine clients.

Route-level identity conditions, JWT/JWKS validation for APIs, and MCP protected-resource metadata with audience and scope checks.

Feature Example

Injectable UX

Useful if you want to: you cannot modify the frontend but need a user badge, a guard, gated controls or a PWA shell.

HTML/JS/CSS injection, declarative UI gating, a 403 banner and a strict CSP — without touching the application source.

Feature Example

Usage events and plugins

Useful if you want to: you need metering, audit, observability, or a commercial extension.

Durable per-type WAL, signed out-of-process plugins, targeted 503 on backpressure and an opaque subjectId instead of user data.
