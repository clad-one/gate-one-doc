Examples

Copyable, schema-validated configurations.

Most examples are real files under examples/ in the product repository. The build validates them against the published JSON Schema; local examples are also checked with gate-one -check. The proxied-site example lives in the source repository, where its runnable demo and userscript live.

ExampleWhat it shows
Getting startedA local demo with the embedded development identity provider, its default users and a user badge.
Direct OIDCOne OIDC issuer used directly, with roles and scopes read from that issuer and no federation or broker.
Multi-app SSOA second application added to the same provider and cookie domain, reusing the login session.
Cross-domain SSOTwo unrelated domains using one IdP session, one provider per domain and a single shared route body.
Keycloak with GoogleA classical external IAM: Keycloak federates Google, Gate One trusts one Keycloak issuer.
Embedded IAMcladone-auth federates Google, maps claims and stores local/federated user grants.
High AvailabilitySeveral Gate One replicas behind a load balancer with shared Redis state.
APIs and MCPA browser provider, a JWT provider, an identity-conditioned API route and an MCP service.
MCP toolsA REST-derived MCP service, a proxied MCP server and an aggregating set, with delegated credentials.
Own account panelThe application’s own burger panel reads the session instead of the built-in user badge.
Injectable UXUser badge, UI gating, injection bundle, 403 banner and a nonce CSP.
Enhance a proxied siteAn external site proxied through Gate One with an injected userscript.
Usage pluginA signed audit plugin, a trust store, the WAL and per-type durability.
IAM + IdP bridgeAn http-bridge provider returning identity and IAM facts, linked to the contract.

  • examples/injectable-ux/routes.json and bundle.json
  • examples/usage-events/routes.json, audit.manifest.json and trust-store.json

The proxied-site example is kept in the source repository: examples/siteproxy/.

Getting started

A local demo with the embedded development identity provider.

Direct OIDC with one IdP

Point Gate One straight at a single OIDC issuer, with no federation and no broker.

Multi-app SSO

Add a second application to an existing login session.

Cross-domain SSO

One IdP login across app-a.com and app-b.fr, with one provider per domain.

Keycloak with Google

Federate Google in Keycloak, then point Gate One at one Keycloak issuer.

Embedded IAM

Federate Google in cladone-auth, map claims and assign user grants.

High Availability

Balance load across several Gate One replicas with shared session and revocation state.

APIs and MCP

A browser provider, a JWT provider and an MCP protected resource.

Own account panel

Replace the built-in user badge with a burger side panel owned by the application.

IAM + IdP bridge

An http-bridge provider returning identity and IAM facts while Gate One keeps policy enforcement.

MCP tools

A REST-derived MCP service, a proxied MCP server and an aggregating set, with delegated credentials.

Injectable UX

Badge, gating, injection bundle, 403 banner and CSP.

Enhance a proxied site

Proxy an external site through Gate One and inject a userscript into every HTML page.

Usage plugin

A signed audit plugin, a trust store and a durable WAL.
