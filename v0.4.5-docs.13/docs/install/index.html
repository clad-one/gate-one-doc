Components and installation

What the components are, where they come from, and how to install Gate One with the optional services.

Gate One is one binary in front of your applications. Everything else — an identity provider, the optional broker, the token broker, Redis — is a separate component you choose to run.

All releases attach a single services_<version>_src.tar.gz containing the token broker and auth-bridge sources. They are not part of the gate-one binary: each runs as its own container.

Minimal install

Gate One + one OIDC provider + a TLS reverse proxy.

  1. Download a release (gate-one_<version>_<os>_<arch>.tar.gz from the release page or a signed dist/), verify it (see Publish and trust a plugin for the trust model), and extract it.

  2. Write api-routes.json — start from Direct OIDC or Keycloak with Google.

  3. Validate, then start:

    export OIDC_CLIENT_SECRET=...        # the authProvider.clientSecretEnv variable
gate-one -check -config api-routes.json
gate-one -config api-routes.json      # listens on :3000

  4. Put it behind the reverse proxy — TLS, the public host, and the OIDC callback URL (see Architecture).

  5. Probe it — /healthz (liveness) and /readyz (readiness).

Add the optional components

Embedded IAM (cladone-auth)

A single Go binary, shipped signed with each release. Configure it and point Gate One at it with authProvider.type: "oidc". See Embedded IAM and the broker configuration.

Token broker

The service behind delegated credentials. It is a separate Node container on the internal network; Gate One declares it in tokenBroker and references a provider per route. Build it from services/token-broker and follow its installation. The browser routes (/connections, /connect/, /oauth/) are published through the login host, not the broker.

auth-bridge

The reference implementation of the HTTP bridge contract. Build it from services/auth-bridge and use authProvider.type: "http-bridge". Gate One still enforces auth, auth.identity and MCP scope checks.

Redis (several replicas)

A single instance uses bbolt. Two or more Gate One replicas need shared state in Redis (Sentinel + TLS + ACL) and the same session key. See Horizontal scaling and the High Availability example.

What is not a component

  • A Backend-For-Frontend is your application behind a backend: route, not a Gate One service.

  • Keycloak, Postgres and other platform services are yours to run; Gate One only needs an OIDC issuer (and Redis for HA).
